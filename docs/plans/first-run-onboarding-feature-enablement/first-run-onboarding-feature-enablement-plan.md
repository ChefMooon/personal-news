# Specification & Overview

### 1. Scope & Objective
- **Goal:** Give fresh installs a guided first-run wizard and give every optional feature a real, non-destructive on/off switch (timers, polling, notifications, manual refresh, and UI all honour it). Existing users are untouched.
- **In-Scope:**
  - A single shared feature manifest (`src/shared/feature-manifest.ts`) for six features: `youtube`, `reddit_digest`, `saved_posts`, `sports`, `weather`, `astronomy`. Scripts is always on, is NOT a feature, and is not in the manifest.
  - New flag `youtube_enabled` (absent means enabled).
  - One central main-process dispatcher plus one `applyEnabled` hook per feature; gating of notifications and manual refresh.
  - Fresh-profile detection and a persisted `onboarding_completed` marker, grandfathering existing profiles.
  - Settings > Features tab (manifest driven, "Needs setup" label, "New" badge) while `?tab=features` keeps working.
  - Hidden-widget layout safety on the dashboard.
  - The wizard UI: pick features, one skippable detail step per selected feature, finish summary with optional "What's in this version".
  - A read-only `updates:getCurrentReleaseNotes` channel.
  - Browser-mock scenarios and Electron harness scenarios, a CHANGELOG bullet, and `docs/HOW-TO-MAINTAIN-ONBOARDING.md` with README, `docs/ui-ux.md`, `docs/HOW-TO-RUN.md`, and `scripts/PLAYWRIGHT-HARNESS.md` pointers.
- **Out-of-Scope:** re-run-setup entry point; mini-wizard on upgrade; auto-enabling new features for existing users; deleting any data; making Scripts a toggle; fixing `NtfyOnboardingWizard` persisting settings on Test Connection; editing `AGENTS.md`; editing `docs/plans/dev-production-database-electron-harness/dev-production-database-electron-harness-plan.md`; rewriting `docs/HOW-TO-RUN.md` or `docs/HOW-TO-RELEASE.md`.

### 2. Technical Constraints & Architecture
- Layers (AGENTS.md): `src/main`, `src/preload`, `src/shared`, `src/renderer/src`. Renderer reaches main only through `window.api.invoke` and the typed channels in `src/shared/ipc-types.ts`. No Node, SQLite, or fs in the renderer. Preload (`src/preload/index.ts`) derives its allowlist from `src/main/security/ipc-policy.ts`, so no preload edit is needed.
- Test and validation commands (all verified in `package.json`): `npm test -- <filter>` (runs `node scripts/run-vitest.mjs run`), `npm run typecheck`, `npm run build`, `npm run test:renderer-browser`, `npm run test:local-test-data`, `npm run test:whats-new-browser`, `npm run test:whats-new`, `npm run test:dashboard-drag`, `npm run test:dashboard-edit`, `npm run test:update-notifications`. This plan adds three scripts: `test:feature-enablement-browser`, `test:onboarding-browser`, `test:onboarding`. Do NOT run `npm run lint` as a check: its script passes `--fix` and rewrites files.
- Tests never use the live production database. Unit tests use in-memory `better-sqlite3` plus a mocked `getDb` (pattern: `src/main/__tests__/dev-test-data.test.ts`) or a mocked settings store (pattern: `src/main/sources/astronomy/__tests__/module.test.ts`). Harness scenarios use the runner-provided temp profile.
- **Flag storage (verified).** `weather_enabled`, `sports_enabled`, `saved_posts_enabled`, `reddit_digest_enabled` are rows in `settings`, written by the renderer as `"true"`/`"false"` through `settings:set` and read as `!== "false"` (absent means enabled; migrations 002 and 003 seed weather and sports to `true`). Astronomy is the `enabled` field inside `astronomy_settings_json`, written through `astronomy:setSettings`. YouTube has no flag today. New rule, one function: `isFeatureFlagValueEnabled(raw, entry) = raw === null ? entry.enabledWhenUnset : raw !== "false"`. All six current features have `enabledWhenUnset: true`. A feature added after this release must use `enabledWhenUnset: false` so existing users get it off.
- **Fresh-profile detection (verified).** `runMigrations` in `src/main/db/database.ts` reads `meta.schema_version` into `currentVersion` before the migration loop; `001_initial.sql` creates `settings`. Fresh means: no `schema_version` row AND no `settings` table, evaluated after `CREATE TABLE IF NOT EXISTS meta` and before the loop. In that same open, a marker row is written: fresh gets `onboarding_completed = "false"`; pre-existing without the row gets `"true"` (grandfather). The fresh DB must be marked `"false"` immediately so that quitting mid-wizard and relaunching (the DB is then no longer "fresh") cannot be mistaken for an existing profile. Missing-key heuristics (`ntfy_topic`, `whats_new_last_seen_version`, empty tables) are rejected.
- **Onboarding mode (mirrors `resolveWhatsNewMode` in `src/main/updates/whats-new.ts`).** Pure function `resolveOnboardingMode({ isPackaged, optIn })`: packaged is `enabled`; otherwise `enabled` only when `process.env.PERSONAL_NEWS_ONBOARDING === "1"`; else `disabled`. So Electron harness runs (`isElectronHarnessRun` in `src/main/harness-mode.ts`) and plain `npm run dev` skip the wizard by default, and `extraEnv: { PERSONAL_NEWS_ONBOARDING: "1" }` on `runElectronHarness` opts a harness run in. The decision is made in `initializeOnboardingState` right after `openDatabase()` and BEFORE `initializeDevTestDataForStartup` in `src/main/index.ts`, so fixture seeding never triggers the wizard (disabled mode on a fresh DB writes `"true"`). When the wizard is required, dev fixture seeding is skipped.
- **Pre-wizard defaults.** In enabled mode on a fresh open only, `initializeOnboardingState` writes `youtube_enabled = "false"` and `saved_posts_enabled = "false"` (the two `needsSetup` features) before any module initializes, so YouTube cron and ntfy polling never run before the user chooses.
- **Dispatcher.** `src/main/features/feature-dispatcher.ts` owns a `Map<FeatureId, hook>`; `dispatchFeatureEnabledChange(id, enabled, previousEnabled)` skips when unchanged. It is called from the `settings:set` handler in `src/main/ipc/index.ts` (replacing the `weather_enabled` branch near L3686) and from the `astronomy:setSettings` handler (~L3558). Hooks live next to their module code. Enable-paths that start timers or network refreshes skip when `isElectronHarnessRun()` (parity with each module's `initialize`); stop-paths always run. The weather hook keeps its pre-existing "refresh after enabling" behaviour.
- **Ordering guarantee used by the wizard.** `settings:set` and `astronomy:setSettings` handlers are synchronous and the renderer's `invoke` calls are delivered in call order, so the wizard may fire the six `setEnabled` calls without awaiting each result.
- **Channels (no new prefix).** New channels reuse the already-allowed `settings:` prefix (`settings:getOnboardingState`, `settings:completeOnboarding`, `settings:markFeaturesSeen`). The release-notes channel is `updates:getCurrentReleaseNotes`; the `updates:` regex alternation in `rendererChannelPrefixes` (`ipc-policy.ts` L14) lists channels explicitly, so that name must be added to it. `onboarding_completed` and `features_seen_ids` are NOT added to `genericSettingKeys`.
- **New badge mechanism.** Setting `features_seen_ids` (JSON array of feature ids). Baseline writes all manifest ids when the marker is first written (fresh or grandfather). Features tab shows "New" for manifest ids missing from that list and marks them seen when the tab unmounts. A later release that adds a feature (with `enabledWhenUnset: false`) automatically shows "New" to every existing user. Feasibility verified: the baseline runs once per profile and a missing or malformed list is treated as "all seen".
- **Hidden-widget layout (verified).** `react-grid-layout` 2.2.4 builds its internal layout from rendered children only (`synchronizeLayoutWithChildren` in `node_modules/react-grid-layout/dist/chunk-QAWP6PEK.js`), so skipping a hidden widget at render does not reserve a grid slot. But `Dashboard.tsx` passes `projectWidgetLayout(layout, cols)` computed over ALL widgets, `moveWidget` (`src/shared/dashboard-grid.ts` L274) swaps with the adjacent id in `widget_order` even if that widget is invisible, and `normalizeWidgetLayout` re-compacts hidden widgets on every commit. Phase 6 fixes this with pure helpers.
- **Not extended:** `DataSourceModule` (`src/main/sources/registry.ts`). Do not add `setEnabled` to it; decided against because the Reddit digest has no source module (it is a bundled script under `src/main/sources/scripts`) and the dispatcher keeps one place to maintain.
